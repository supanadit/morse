# Bot MCP Servers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the New bot wizard and Edit bot add, edit and remove MCP servers for one bot, writing each engine's native file without running `pi` or `opencode`.

**Architecture:** `BotEngineConfig`/`BotEngineState` gain an `mcpServers` list in one neutral shape. Each integration's `BotEngineLayout` writes and reads it in its own format (`config/mcp.json` for pi, the `mcp` key of `config/opencode/opencode.json` for OpenCode). The protocol carries the list on `bot/create`, `bot/update` and `bot/config`; the wizard gets an optional MCP step built as a small child component. pi's `settings.json` also gains its published `$schema`.

**Tech Stack:** TypeScript ESM, Node `fs`, Vitest, Angular 22 signal inputs/outputs, OnPush.

**Spec:** `docs/superpowers/specs/2026-11-14-bot-mcp-design.md`

## Global Constraints

- No new dependencies; no `pi`/`opencode` CLI invocation for any write or read in this feature.
- Bot config files are private: directories `0700`, files `0600`, temp-file-then-rename atomic writes.
- Engine format knowledge stays in `packages/integration-*`; `@morse/system` holds only the neutral shape and validation.
- `mcpServers` on `BotEngineConfig` is tri-state: absent leaves the file alone, present replaces the managed set, `[]` clears it.
- Server names match `^[A-Za-z0-9_-]+$` and must not be `__proto__`, `prototype` or `constructor`.
- Omit `enabled` when true and `exposure` when absent; never invent values.
- TS imports use the repo's `.js` suffix convention.
- Commit after each task with the message shown in that task.

## Review Focus

- A corrupt `mcp.json` must not make the rest of Edit bot unreadable (it would submit an empty persona over the real one) — covered in Task 2.
- A hand-written pi entry without `type` must survive an edit instead of being dropped — covered in Task 2.
- Removing the last server must remove the `mcpServers`/`mcp` key, not leave `{}` — covered in Tasks 2 and 3.
- Env/header text containing `=`, `:`, blank lines or duplicate keys must parse predictably — covered in Task 4.
- Invalid, duplicate and prototype-key names must be refused at the host boundary — covered in Task 1.

- [ ] **Step 3: Implement the pi mapping**

In `packages/integration-pi/src/bot-layout.ts`:

```ts
const MCP_FILE = 'mcp.json';

export function piMcpPath(botRoot: string): string {
  return join(piAgentDir(botRoot), MCP_FILE);
}
```

Add private helpers:

```ts
function readPiMcpServers(path: string): BotMcpServer[] | undefined
function writePiMcpServers(path: string, servers: readonly BotMcpServer[]): void
function piMcpEntry(server: BotMcpServer, kept: unknown): Record<string, unknown>
```

`readPiMcpServers` wraps `readMcpFile` in `try`/`catch` and returns `undefined` on any throw. For each entry: skip when `definesMcpServer(entry)` is false (pi project override). Infer `type` as `'http'` when `entry.type === 'http'` or (`entry.url` is a string and `entry.command` is undefined), else `'stdio'`. Skip a stdio entry with no non-empty `command` and an http entry with no non-empty `url`. Emit only present optional fields, plus `enabled: entry.enabled !== false`.

`writePiMcpServers` reads the file with `readMcpFile` (treat a missing file as empty), keeps every existing entry that is not a server (`!definesMcpServer`) or whose name is in `servers`, then sets each listed entry via `piMcpEntry`. When the result is empty, write the file without `mcpServers`; otherwise write it with the merged object. Use `writePrivateJson`.

`piMcpEntry` spreads the existing entry, deletes every key Morse owns (`type`, `command`, `args`, `env`, `cwd`, `url`, `headers`, `enabled`, `exposure`), then writes `type` and the transport's fields. Add `enabled: false` only when `server.enabled === false`; add `exposure` only when defined. Keep `cwd`, `args`, `env`, `headers` only when non-empty.

In `writePiBotConfig`, after the settings block:

```ts
if (config.mcpServers !== undefined) {
  writePiMcpServers(piMcpPath(botRoot), config.mcpServers);
}
```

In `piBotLayout.read`, before the return:

```ts
const mcpServers = readPiMcpServers(piMcpPath(botRoot));
```

and add `...(mcpServers === undefined ? {} : { mcpServers }),` to the returned state.

Export `piMcpPath` from `packages/integration-pi/src/index.ts` beside `piAgentDir`.
